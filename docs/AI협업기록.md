### 인터뷰 3라운드 (같은 날)

- 내가 알려 준 사실: Probe station 측정은 수업에서 직접 했다. 다만 분석에 쓴 15개 TFT 파일은 수업에서 대대로 내려오는 측정 자료다. 우리 조가 직접 측정한 자료는 따로 있고, 소자가 오래되어 지저분하다. 수업 과제(Check Point 5번)는 "TFT 측정 data를 그래프로 표현하고 parameter를 추출하라"였다.
- 내 결정: 절연막 용량 1.75×10⁻⁸ F/cm²을 세 재료에 똑같이 쓰는 것은 수업 진행을 위한 값이므로 따지지 않는다. AI가 기준표 7번 후보로 올렸지만 뺐다.
- 내 결정: 이름에 TFT가 들어가야 한다. AI가 추천한 "다시 계산 노트 / recheck-notes"는 거절.
- 받아들임: 기준표의 완성 기준(항목마다 사례, 다시 계산하는 명령, 내가 직접 확인한 기록). N은 미리 정하지 않는다.
- 가정: 절연막 용량은 수업에서 준 값을 그대로 쓴다. 이 값이 틀리면 이동도의 절대값은 같은 비율로 틀리지만, "구간에 따라 몇 배 달라지는가"는 바뀌지 않는다.

### 수업 자료 `8주차.pdf` 조사 (같은 날, 하이쿠 서브에이전트)

- 수업 자료에는 피팅 구간을 고르는 기준이 없다. 구체적인 구간은 SigmaPlot 예시 코드의 `startvg=15`, `endvg=20` 하나뿐이다. (AI가 추출한 글에서 이 두 줄을 직접 다시 확인함)
- 절연막 용량 값은 수업 자료에 `C = ZZ`로 비어 있다. 1.75×10⁻⁸은 실습 스크립트(`시그마실습*.txt`)에 적힌 값이다.
- 수업 자료의 포화 영역 식과 절차(√I를 전압에 대해 직선으로 맞추고 기울기와 절편으로 이동도와 문턱전압을 구함)는 기존 도구가 쓰는 방법과 같다.
- 수업 자료의 박막 두께 예시는 10700 Å인데 기존 도구는 40·50 nm를 쓴다. 어느 쪽이 우리 시료의 값인지 모른다. (확인 필요. Tauc는 사례 한 건으로만 쓰므로 지금은 따지지 않는다)
- 서브에이전트가 보고한 나머지 내용(그림에서 읽은 수치, 자료 안의 표기 불일치 8건)은 AI가 다시 확인하지 않았다.

## 2026-11-14 · 설계 승인, 0단계

### 내가 내린 결정과 이유

- 설계(`docs/설계.md`)를 승인했다.
- 화면 디자인 스킬은 AI가 추천한 Anthropic 공식 스킬 대신 `leonxlnx/taste-skill`의 `design-taste-frontend`를 설치하게 했다. 시안 수정은 다시 소넷에게 맡기게 했다.

### 0단계에서 한 일

- 새 폴더에 git 저장소를 만들었다(브랜치 `main`). 커밋은 아직 하지 않았다.
- `.gitignore`로 원자료 형식(`*.DAT`, `*.JNB`, `*.xfm`, `*.csv`)을 막았다. `git check-ignore`로 `IGZO2004.csv`, `aSi2002.DAT`, `LTPS1002.JNB`가 막히는 것을 확인했다.

### AI가 알린 위험

- taste-skill 설치 화면에 보안 평가가 "Gen: Critical Risk, Snyk: Med Risk, Socket: 0 alerts"로 나왔다. AI는 이 스킬의 스크립트를 실행하지 않고 글(SKILL.md)만 디자인 기준으로 읽게 했다.

### 1단계: 원자료 읽기

- AI가 `recheck/read_raw.py`(원자료 읽기), `recheck/__main__.py`(명령 창구), `tests/test_read_raw.py`(확인 5개)를 썼다.
- `python -m recheck files`로 15개 파일을 요약했다. 모든 파일의 MOBILITY 측정이 201점이다.
- AI가 파이썬 코드와 무관한 방법(awk)으로 같은 표를 다시 뽑아 비교했다. 점 수, 첫 줄, 끝 줄, 음수 전류 개수가 15개 모두 같았다.
- 음수 전류 개수: 기존 도구가 공개했던 9개 파일만 더하면 IGZO 63(21×3) + LTPS 599(200+199+200) + a-Si 2 = 664. 검수 보고서의 664와 같다. 이 숫자는 이제 "새 코드로 다시 확인됨"이다.
- 표에서 바로 보인 것: `IGZO2002`의 끝 줄 전류가 6.67e-06 A로, `IGZO2004`(1.87e-04 A)보다 훨씬 작다. 채널이 더 짧은 소자인데 전류가 더 작다. (기준표 5번 사례)
- 내가 직접 확인할 것(아직 안 함): 원자료 한 파일을 메모장으로 열어 첫 줄과 끝 줄 숫자를 표와 대조. 파일 이름의 W/L 읽는 법이 맞는지.

### 1단계의 직접 확인을 건너뜀

- 메모장 대조와 W/L 확인을 부탁받았지만 "몰라, 네가 해 줘"라고 하고 2단계로 넘어가게 했다. 그래서 1단계는 **AI만 확인한 상태**다. 파일 이름의 W/L 읽는 법은 계속 가정이다.
- AI가 알린 것: 기준표의 N은 내가 직접 확인한 항목 수라서, 이렇게 넘어간 확인은 나중에 직접 해야 N에 들어간다.

### 2단계: 한 구간의 이동도와 문턱전압

- AI가 `recheck/fit.py`(직선 맞춤, 이동도, 문턱전압)와 `tests/test_fit.py`(확인 6개)를 썼다. 명령은 `python -m recheck fit IGZO2004.csv 5.5 9.5`.
- 확인 방법 세 가지: ① 답을 아는 직선(y = 2x + 1) ② 파이썬에 들어 있는 직선 맞춤과 같은 답인지 ③ 이동도 10, 문턱전압 2 V로 식에서 만든 가짜 소자를 넣어 10과 2가 되돌아오는지(양전압, 음전압 둘 다).
- 검수 보고서의 값과 대조했다. 모두 일치: IGZO2004 5.5~9.5 V → 8.07 / 2.631 V / R² 0.9982, 5~9 V → 7.44, 6~10 V → 8.76, 15~18 V → 51.0, LTPS1005 −13~−8 V → 181, aSi2002 13~18 V → 0.284, IGZO2002 3~8 V → 0.207. 이 값들은 이제 "새 코드로 다시 확인됨"이다.
- AI가 틀렸던 것: 처음 쓴 코드는 부탁한 구간이 측정 범위를 넘어도 아무 말 없이 잘린 범위로 계산했다. 수업 예시 15~20 V를 IGZO2004에 넣었더니 15~18 V와 똑같은 값(51.03, 31점)이 나와서 AI가 알아챘다. IGZO 측정은 18 V에서 끝난다. 실제로 쓴 전압 범위를 함께 출력하도록 고치고 확인을 하나 추가했다.
- 여기서 알게 된 것: 수업 예시 구간 15~20 V는 IGZO 자료에는 그대로 적용할 수 없다(측정이 −2~18 V).
- 커밋을 맡겼지만 이 PC에 git 사용자 이름과 이메일이 설정되어 있지 않아 실패했다. 이메일은 공개 레포에 드러나므로 AI가 임의로 정하지 않고 나에게 물었다.
- 내 결정: 기존 레포와 같은 이름·이메일을 쓴다. AI가 이 레포에만 설정하고 0·1·2단계를 커밋 세 개로 남겼다. (`recheck/__main__.py`는 1단계와 2단계 내용이 한 파일에 섞여 있어 2단계 커밋에 함께 들어갔다.)
